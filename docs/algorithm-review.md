# 算法评审说明

## 目标

系统只向用户交付同时满足以下条件的结果：

1. 仍是同一个人。
2. 构图、头顶、发冠和四边画幅安全。
3. 用户选择的目标变化真实发生。
4. 未选择的眼、鼻、唇、眉、发型等区域保持锁定。
5. 没有脸部横向放大、颧骨外扩、颧下凹陷等已知风险。

## 统一流水线

`iPhone 本地前检 → 方案编译 → 并行候选 → 确定性几何检测 → OpenAI 多模态裁判 → 合格候选排序 → 最多 2 轮定向纠偏 → 原图安全回退`

- 自然修图默认先生成 1 张，边界结果再补候选。
- 明显修图与医美目标预演默认先生成 1 张；未通过时按失败码定向生成下一张。
- 画幅、分辨率和头发边界等确定性硬失败在多模态裁判前拦截。
- 候选只有在没有 `hardFailures` 且全部分数达到门槛时才能交付。
- 所有候选不合格时返回原图，不展示“风险最低但仍不合格”的结果。
- V2/V3 始终以原图作为身份、构图与锁定区域基线。

## 已知评审问题

- 如何减少 Gemini 候选数量和多模态质检次数，同时保持硬失败展示率为 0。
- 如何提高远景、小脸、侧脸与复杂光线下的几何检测稳定性。
- 如何让“明显修图”的目标变化具有可测量、可解释的验收标准。
- 如何提高身份相似度与结构变化之间的 Pareto 前沿。
- 如何校准语义裁判分数并降低模型自洽但视觉错误的情况。
- 如何验证多个医美方向始终完整保留，不坍缩为单一方向。

## 测试

`backend/tests/golden/manifest.json` 定义了不包含真人素材的 14 类事故场景。确定性测试覆盖评分、门槛、候选选择、纠偏指令、集合完整性与安全回退；真实模型验收使用仓库内的 3 张虚构合成人像，并增加 3 组 V2/V3 三图裁判。
