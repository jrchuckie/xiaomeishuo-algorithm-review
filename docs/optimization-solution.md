# 小美说算法优化落地方案

## 1. 目标与验收口径

本轮不以“换一个更大的模型”为主要方案，而是同时优化生成链路、质量门禁和偏好闭环。

| 目标 | 核心指标 | 第一阶段验收线 |
|---|---|---:|
| 更快 | P50 / P95 端到端耗时 | P50 降低 30%，P95 降低 20% |
| 更稳 | 硬失败展示率 | 0 |
| 保持本人 | 身份通过率、未选区域通过率 | 均不低于 95% |
| 变化明显 | 明显模式目标变化通过率 | 不低于 80% |
| 越用越懂 | 二次修改率、满意保存率 | 二次修改率下降 20% |

所有指标按人像难度分桶统计：正脸 / 侧脸、近景 / 远景、遮挡、复杂光线、多人背景。不能只看全量平均值。

## 2. 生成链路

```text
iPhone 本地前检
  -> 审美画像与修图方案编译
  -> 单候选快速生成
  -> 确定性安全前检
  -> 多模态语义裁判
  -> 合格即返回
  -> 不合格时按失败码定向纠偏（最多 2 轮）
  -> 仍不合格则返回原图
```

### 已落地的速度优化

1. 明显修图和医美预演默认先生成 1 张，不再无条件并行生成 2 张。
2. 画幅错误、低分辨率、头顶或发冠边界损坏等确定性硬失败先拦截，不调用多模态裁判。
3. 只有失败时才根据具体失败码生成下一张，避免盲目重复抽样。
4. 埋点拆分生成候选数、多模态裁判数、确定性拒绝数和纠偏轮次，便于核算真实时延与成本。

如线上黄金集显示单候选通过率不足，可通过 `JUDGE_INITIAL_VISIBLE_CANDIDATES` 或 `JUDGE_INITIAL_MEDICAL_CANDIDATES` 临时恢复为 2，无需改代码。

## 3. 保持本人且变化明显

### 3.1 双基线

- 原图永远是身份、构图和未选区域的唯一基线。
- 上一版结果只用于理解用户反馈，不能成为身份基线。
- V2/V3 必须重新从原图生成，避免脸型、眼睛和五官逐版累积漂移。

### 3.2 区域合同

每次生成前把方案编译成两份清单：

- `allowed_changes`：用户确认且有审美证据的部位与变化方向。
- `locked_regions`：所有未选部位、身份、背景、构图、发型、服装与配饰。

裁判同时检查“允许变化是否发生”和“锁定区域是否保持”，防止模型用放大眼睛、加妆、锐化或改变光线来假装完成脸型目标。

### 3.3 门禁顺序

1. 确定性检查：文件可读、分辨率、宽高比、四边与头发边界。
2. 身份检查：本人、年龄感、表情、视线、面部比例。
3. 锁定区检查：眼、鼻、唇、眉、发型等未选区域。
4. 风险检查：脸部横向放大、颧骨外扩、颧下凹陷。
5. 目标变化检查：明显模式不能只改变肤质、妆感或锐度。

任一硬失败均不可被其他高分抵消，也不可展示“相对最好但仍不合格”的候选。

## 4. 用户偏好学习

偏好学习采用本地优先，不建立服务端长期人脸数据库。

### 信号优先级

1. 用户明确文字反馈，例如“头脸再小一点，但眼睛不要动”。
2. 用户满意并保存的方案及其启用区域。
3. 用户主动选择、取消或长期锁定的部位。
4. 参考图中跨多张重复出现的审美特征。

本次已将“满意保存”和“不满意反馈”统一为校准信号，并修复历史信号取样顺序，始终使用最近 12 条有效信号按时间顺序更新画像。

### 后续升级

- 把自由文本归一化为 `区域 + 方向 + 强度 + 正/负反馈 + 置信度`。
- 对冲突偏好做时间衰减，不把一次偶然反馈永久写入画像。
- 将“本人偏好”与“某张照片的修图要求”分开，避免把临时光线问题误学成长期审美。
- 画像更新采用版本号，可回滚并对比更新前后的满意保存率。

## 5. 评测与灰度

### 离线黄金集

至少覆盖以下事故：身份漂移、眼睛误放大、脸部横向变宽、颧骨外扩、颧下凹陷、头顶裁切、构图变化、明显模式只磨皮、多目标医美方向缺失、V2/V3 累积漂移。

每个样本保留：原图、允许变化、锁定区域、期望失败码、人工评分和模型裁判评分。阈值只能在黄金集上标定，不能凭单个案例调整。

### 上线顺序

1. 影子模式：新裁判只记录，不影响用户结果。
2. 10% 灰度：比较耗时、通过率、安全回退率与人工盲评。
3. 50% 灰度：重点观察困难分桶和二次修改率。
4. 全量：硬失败展示率持续为 0 后再扩大。

## 6. 当前边界

仓库没有真实用户照片与线上密钥，因此现阶段只能验证确定性门禁、流程控制、提示词合同和 Mock API。身份相似度、部位几何和目标变化阈值，必须用经授权的非隐私黄金集与真实模型调用完成最终标定。
