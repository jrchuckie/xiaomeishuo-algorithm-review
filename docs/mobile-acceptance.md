# iPhone App 端到端验收

## 验收口径

本项目的交付对象是 iPhone App，而不是一个孤立的模型接口。移动端验收链路固定为：

`相册选图 → iPhone Vision 本地前检 → 压缩上传 → 方案确认 → 生成与质检 → App 本地保存 → 原图/V1/V2/V3 对比 → 满意/反馈沉淀为偏好信号`

## 已验证项

| 项目 | 结果 | 证据 |
|---|---|---|
| 本地人脸前检 | 通过 | Vision 可识别人脸数量、置信度、边界、朝向和 76 个 landmarks |
| 3 张固定图耗时 | 冷启动 409 ms；热路径 9 ms / 9 ms | `scripts/run_local_vision_poc.sh` |
| 手机上传压缩 | 通过 | 参考图 1280px；分析图 2048px；生成图 3072px，避免上传原始超大照片 |
| V2/V3 请求合同 | 通过 | 每轮同时上传原图、上一版和文字反馈；原图是身份与构图基线 |
| 本机私有存储 | 通过 | SwiftData + Application Support；图片使用 complete file protection |
| 不合格结果展示 | 0 | 后端回传原图；App 明示“当前画面是原图”，禁用“保存新结果” |
| API Key 隔离 | 通过 | App 工程只含网关地址和临时 App Token；模型 Key 仅在服务端环境变量 |
| iOS 源码解析 | 通过 | 全部 Swift 源码经 `swiftc -parse` |
| iOS SDK 类型检查 | 已接入 CI | GitHub macOS Runner 使用 iOS 17 SDK 执行 `ios/check-ios.sh` |

固定测试图均为虚构合成人像，不包含真人用户数据。

## App 行为约束

- 生成超时使用移动端可理解的网络提示，原图和已保存版本不会丢失。
- `safe_original` 不使用普通成功样式，不允许用户误把原图当作新版本保存。
- V2/V3 未提及区域默认锁回原图，上一版只用于指出问题，不能作为身份基线继续累积变化。
- 用户“满意并保存”以及“不满意并要求纠正”都会形成最多 12 条本地校准信号，下一次审美档案生成时按时间顺序提交。
- 医美结果页同时生成第二张“变化说明图”：根据确认方案在目标图上叠加箭头与区域标签，可单独保存；干净效果图不写入任何标识。

## 仍需产品方完成的上架项

算法与代码验收不等于 App Store 发布。正式上架前仍需产品方提供 Apple Team、签名、Provisioning Profile、生产 API 域名、隐私政策和真机网络测试环境；这些敏感配置不进入评审仓库。
